    Cloud API — Developer Setup Guide

    Everything a developer needs to do to make the Cloud API fully operational from scratch.

    1. Prerequisites

    • Python 3.11+
    • Docker Engine with the Docker Compose plugin
    • A Supabase project (free tier is fine)
    • An OpenRouter API key (routes all LLM calls)

    2. Python Dependencies

    The root setup script creates the shared .venv and installs both desktop and Cloud API dependencies:

    ./setup.sh

    Cloud API and Celery run natively from this environment. Docker is used only for Redis.

    3. Environment Variables

    Create a file at cloud_api/.env. Never commit this file.

    # ── Supabase ─────────────────────────────────────────────────────────────────
# Found in: Supabase Dashboard → Project Settings → API
SUPABASE_URL=https://your-project-id.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJI...   # "service_role" secret key (NOT the anon key)

# ── OpenRouter (LLM gateway) ───────────────────────────────────────────────
OPENROUTER_API_KEY=your-openrouter-key-here
# OPENROUTER_API_BASE=https://openrouter.ai/api/v1
# OPENROUTER_APP_URL=https://your-app.example
# OPENROUTER_APP_TITLE=Nolain Data Query

# ── LLM catalog (optional override) ─────────────────────────────────────────
# LLM_MODELS_CONFIG=/absolute/path/to/custom_llm_models.yaml

# ── Stripe credit purchases (optional) ──────────────────────────────────────
# STRIPE_SECRET_KEY=sk_test_...
# STRIPE_WEBHOOK_SECRET=whsec_...
# STRIPE_PRICE_CREDITS_JSON={"price_basic":"1000","price_team":"10000"}

    Copy from cloud_api/.env.example and fill in real values.

    Policy files (defaults; some settings have env overrides — see Billing):

    File Purpose
    app/config/llm_models.yaml Model catalog, OpenRouter slugs, default model
    app/config/billing.yaml Credits per dollar, surplus rate, rate overrides
    app/config/generation.yaml Retry budgets, chain attempt ceiling, adaptive Pandas repair profiles

    Pandas repair settings

    No setting is required for normal users. Server operators may tune:

    • cloud_api/app/config/generation.yaml
    • pandas_sandbox_max_retries: in-cloud retries for truncated, empty, or statically rejected code
    • pandas_max_retries: local-execution repair jobs
    • pandas_total_max_attempts: hard ceiling across the complete Pandas chain
    • pandas_repair_profiles: reasoning effort and max_tokens selected by failure category and retry index
    • pandas_repair_reasoning / pandas_repair_max_tokens: fallback profile
    • cloud_api/app/config/llm_models.yaml: first-pass model defaults and maximum completion tokens. Repair profiles override reasoning and token settings only on repair calls.

    Restart the API and Celery workers after changing these YAML files because configuration is cached by each process.

    Why the service-role key? The API reads and writes the clients_nolain_query table to validate keys. Credit balances live on profiles_nolain_query.credit_balance. The anon key cannot do this (Row-Level Security blocks it). The service-role key bypasses RLS and must stay server-side only.

    4. Database Setup (Supabase)

    Run the SQL migrations once in your Supabase project:

    1. Open the Supabase Dashboard → SQL Editor.
    2. Fresh projects — run in order:
    3. cloud_api/sql/001_create_clients.sql
    4. cloud_api/sql/002_auth_users.sql
    5. cloud_api/sql/003_account_balance.sql
    6. Existing databases that still have a query_balance column should also run cloud_api/sql/008_credit_rename.sql.

    Files 004–007 are historical upgrades superseded by 003 / 008; do not run them on a new project.

    This creates the clients_nolain_query table, portal profiles, credit balances, and ledger RPCs.

    Schema overview

    Column Type Purpose
    id uuid Internal primary key
    api_key text The secret token validated on every request
    tier text owner / premium / free
    user_id uuid Portal account that owns the key (required for credits)
    is_active boolean false = key is suspended
    created_at timestamptz When the key was issued

    5. Inserting the Owner Key

    The owner key is inserted directly into the database (it is never hard-coded in source). It is intended as an unlinked developer credential: no user_id, no credit checks. Do not attach it to a portal profile unless you want it to spend that account's credits like any other linked key.

    Generate a secure token:

    python3 -c "import secrets; print('sk-owner-' + secrets.token_hex(16))"
# Example: sk-owner-3f9a1c72b4de5e01a8c9d2e3f4b5c6d7

    Insert it in the Supabase SQL Editor (or adapt cloud_api/scripts/ensure-developer-key.sql):

    insert into public.clients_nolain_query (api_key, tier, label, is_active)
values (
    'sk-owner-3f9a1c72b4de5e01a8c9d2e3f4b5c6d7',
    'owner',
    'Developer (unrestricted)',
    true
);

    Save this key somewhere safe (e.g. a password manager). It is your root credential.

    6. Inserting Client Keys (Portal / Manual)

    The Nolain portal website will do this automatically when a user registers and requests a key. For now, insert keys manually:

    # Generate a free-tier key
python3 -c "import secrets; print('sk-free-' + secrets.token_hex(8))"

    -- Insert a free-tier client
insert into public.clients_nolain_query (api_key, tier)
values ('sk-free-abcdef1234567890', 'free');

-- Insert a premium-tier client
insert into public.clients_nolain_query (api_key, tier)
values ('sk-premium-1234567890abcdef', 'premium');

-- Deactivate a key
update public.clients_nolain_query set is_active = false where api_key = 'sk-free-abcdef1234567890';

    7. Starting the Services

    The Cloud API now uses an asynchronous architecture with Celery and Redis.

    From the repository root, start all cloud development services in one terminal:

    ./scripts/launch-cloud-dev.sh

    The launcher:

    • starts only Redis from cloud_api/docker-compose.dev.yml;
    • waits for Redis before starting the native processes;
    • runs Uvicorn and Celery from the root .venv;
    • waits for both services to become ready; and
    • stops Uvicorn, Celery, and its Redis container on exit.

    Start the desktop stack in a second terminal:

    ./launch.sh

    Press Ctrl+C in each terminal to stop that launcher's services. The Cloud API health endpoint is http://127.0.0.1:8000/health; the local execution engine is http://127.0.0.1:8001/health.

    For production: - Use gunicorn with Uvicorn workers for the API. - Use a process manager like supervisord or systemd to keep the Celery worker alive.

    8. Authentication Flow (Code Reference)

    API key auth (desktop app / Cloud API)

    • app/core/db.py — Supabase client singleton (reads SUPABASE_URL + SUPABASE_SERVICE_ROLE_KEY).
    • app/core/security.py — get_api_key() FastAPI dependency; validates key and enforces remaining credits.
    • app/routers/generation.py — Injects ClientContext via Depends(get_api_key).

    Credit enforcement logic

    1. Look up api_key in clients_nolain_query.
    2. Unlinked owner keys (tier = 'owner', no user_id) skip credit checks and charges.
    3. Portal-linked keys (any tier, including owner with user_id): read profiles_nolain_query.credit_balance; return HTTP 402 when balance is empty.
    4. Unlinked non-owner keys: return HTTP 402 (not linked to a portal account).
    5. Otherwise proceed. Each LLM call charges credits immediately from token usage plus surplus (app/core/llm_billing.py, app/core/credit_pricing.py).

    LLM routing

    • app/core/llm_config.py — OpenRouter client factory and model catalog (llm_models.yaml).
    • app/routers/llm.py — GET /api/v1/llm/models for client model selection.
    • Requests pass an optional model field (catalog id, e.g. deepseek-v4-flash-0731); omit it to use the server default.

    Stripe top-ups (optional)

    • app/routers/billing.py — POST /api/billing/stripe/checkout and webhook handler.
    • Requires STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET, and STRIPE_PRICE_CREDITS_JSON.

    Portal auth (Google + Supabase, /api/auth/*)

    See Authentication setup for Google Cloud and Supabase dashboard configuration.

    • app/core/user_auth.py — Validates Supabase Bearer tokens via get_current_user.
    • app/routers/auth.py — Account profile and API-key CRUD for signed-in users.
    • sql/002_auth_users.sql — Profiles table and clients_nolain_query.user_id linkage.

    9. Rotating the Owner Key

    1. Generate a new key (step 5 above).
    2. Insert the new key into clients_nolain_query with tier = 'owner'.
    3. Set is_active = false on the old key (or delete it).
    4. Update your password manager / secrets store.

    No server restart required — the change takes effect on the next request.
