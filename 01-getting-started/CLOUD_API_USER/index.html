    Ask your first question with nolainquery

    nolainquery combines a desktop application with a hosted reasoning service called the Cloud API. The desktop reads a file on your computer, sends the Cloud API a compact description of that file, and runs the returned analysis locally. This guide takes you from sign-in to an observable answer.

    Before you begin

    You need:

    • the nolainquery desktop app running; to build it from the public repository, follow Try nolainquery locally
    • a Google account for portal sign-in
    • a positive credit balance
    • one local .csv or .parquet file

    The preprocessing layer also implements .xlsx and .xls, but the current desktop file chooser exposes only CSV and Parquet. Excel is therefore not part of the supported desktop first-use path yet.

    Create an account and API key

    The portal is the website where you sign in, view your balance, and manage API keys. An API key authorizes the desktop to use the Cloud API and spend credits from your account, so treat it like a password.

    1. Open nolainquery.com/login.
    2. Choose Continue with Google and complete sign-in.
    3. In Account → API Keys, optionally enter a label such as Laptop, then choose Create key.
    4. Copy the new key immediately. The full value is shown only once; store it in a password manager.

    The portal supports up to five active keys. If a key is lost, revoke it in Account → API Keys and create a replacement.

    Connect the desktop

    1. Open Settings in the desktop sidebar.
    2. Paste the key into API Key.
    3. Choose Save API Key.

    The desktop validates the key against the Cloud API. Success is visible as a status badge showing the remaining credit balance and account tier. The key is stored on this device and sent to the Cloud API only to authenticate requests.

    If the badge reports a missing, invalid, or zero-credit key, use the matching steps in Troubleshooting before continuing.

    Open a file and ask

    1. Open Home and choose Choose dataset.
    2. Select a .csv or .parquet file. The Home view shows the active filename, row and column counts when available, data-quality summaries, and a row preview.
    3. Open Ask Queries.
    4. Enter a concrete question that uses columns in the file, for example:

    What is the total revenue by country?

    1. Choose Ask, or press Ctrl+Enter on Linux and Windows (Command+Enter on macOS).

    During the request, the desktop reports stages such as Analyzing data, Thinking, and Executing. A successful turn ends with an answer card and calculation evidence in the adjacent workspace. Generated Pandas code is available in Code. If Computation graph was enabled before the request, Graph is also available.

    The full file is not uploaded in this workflow. The cloud receives your question and a compact file description containing schema and summary metadata; that description can include sample values. Generated code and optional graph artifacts return to the desktop, which computes the answer against the local file.

    Know the current boundary

    The implemented capability covers descriptive analysis of one file, including aggregations, comparisons, rankings, historical trends, quality checks, transformations, and optional charts. Forecasting, statistical inference, optimization, and anomaly detection are currently unavailable. nolainquery labels those requests as out of scope instead of presenting them as completed work.

    Due to the generative nature of the label classifier, there might be cases in which a query involving one of those tasks is answered. However, the capabilities of the system are not thougt for giving such type of analysis, and therefore, such answers might be limited in their analysis.

    Some schema-only questions, such as “What columns do I have?”, can be answered from the file description without generating code. An unrelated question gets a short refusal.

    If the first request does not complete

    • Key rejected: see API key recovery.
    • No balance: see credit recovery.
    • Request refused: see unsupported and out-of-scope requests.
    • Service or execution failure: see service and runtime recovery.

    You now have the shortest hosted workflow: a local file, a portal-issued key, and an answer computed on your device.

    Continue with Desktop workflows to explore the rest of the implemented workspace, then read Credits before estimating ongoing use.
