    Clarifications

    A question like “top countries by revenue” is clear English and still underspecified for a file. Revenue might be Quantity * Price, or a column that already holds a total. “Top” might mean a count, a percentile, or a threshold. This chapter is how Nolain decides whether to ask, what to ask, and how the answer is used — without gluing that answer onto the question as extra prose.

    If you have not read A conversation from start to finish, start there. This chapter is the clarification turn in detail.

    What a clarification is

    A clarification is a pause in the Ask Queries loop. Semantic reading has found a term whose mapping onto the sketch is not unique. The desktop shows the term, a short reason, and a short list of interpretations, always ending with Other (please specify). You pick one meaning. Generation then continues with that meaning treated as settled.

    The product asks only when the fork would change the calculation. A choice between a normal group-by and a normal sum is not a clarification; the Planner can take that on its own.

    The three-stage pipeline

    Semantic reading is a three-stage pass (SemanticAgent).

    1. Noun chunks (spaCy). The question is split into atomic phrases. Filter values (France, £50), interrogatives, and aggregation heads (“average”, “total”) are dropped. Adjectives such as “top” are kept separately as modifiers.
    2. Schema-grounded routing. Each surviving noun is compared to the sketch — column names plus type, description, and sample values — using vector similarity. Match count picks a specialist:
    3. no column match → granularity (unit of analysis)
    4. several matches → polysemy (which column)
    5. one match → aggregation path (what to compute)
    6. adjective → modifier (how to operationalise “top”, “recent”, …)
    7. Specialists, then merge. The four specialists run in parallel. If one of them fails, the others still stand. Only if all invoked specialists fail does the turn fall back to “please rephrase.” Findings are then deduplicated by term, ranked (polysemy first), and capped (default: two questions). Asking four things before a first result is where people leave.

    spaCy is loaded once per process. Agent instances are reused per model, so a conversation turn does not pay a fresh model load.

    Similarity cutoffs and the cap live in cloud_api/app/config/generation.yaml (semantic_similarity_threshold, semantic_column_match_threshold, semantic_max_concepts).

    When spaCy is missing, a single open-ended prompt replaces stages 1–2. That path still merges and caps.

    The session glossary

    A chosen meaning is stored on the conversation session (resolved_clarifications). It is a glossary for this file and this session, not a note attached to one question. If you have already said that revenue means Quantity * Price, the next unrelated question on the same session will not ask again.

    Newer choices override the same term. A new session starts empty. Terms are matched by lemma, not by substring: a resolved “order” does not silence a later “reorder rate.”

    API fields and prompt fields

    The conversation API receives choices as clarifications[].chosen_interpretation. The choice is not appended to the question as [Clarification: 'revenue' means '…']. The query string stays the query. The resolved pairs travel as a structured field on the worker config (clarifications), then into a dedicated prompt slot ({clarifications}) as JSON:

    [{"term": "revenue", "means": "Quantity * Price"}]

    Empty means (none). Custom text from Other (please specify) is length-limited and stripped of control characters and newlines before it is stored or sent to a model. The generate and repair prompts treat that JSON as user-supplied data that defines terms — not as instructions.

    On the desktop, Rephrase question puts the original question back in the Conversation Input so you can edit it. It does not discard the wording.

    Shortcut

    When the desktop resends with a clarifications payload, classification and semantic reading are skipped. The meaning is treated as settled; the server admits the Plan with the current graph and chart toggles.

    Fallbacks and tuning boundaries

    If spaCy is unavailable or deterministic parsing fails, a single open-ended model call replaces parsing and routing. If every invoked specialist fails, or that fallback cannot produce a valid result, the conversation asks the user to rephrase and does not generate.

    Three current settings tune detection rather than change the product contract: candidate deduplication similarity, schema-column match similarity, and the maximum number of concepts shown (default two). Raising recall can create more interruptions; tightening the thresholds can miss real ambiguity. The stable boundary is that clarification is reserved for choices that can materially change the calculation.
