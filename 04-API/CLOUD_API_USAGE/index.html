    Cloud API — Usage Reference

    This document covers how to call the Cloud API endpoints, with full cURL examples and parameter references.

    The Cloud API turns a natural-language question plus dataset metadata into Artifacts for local execution: Pandas code (code_pandas), an optional computation-graph DAG (dag), and an optional chart contract (visualization_spec). The Cloud API never receives the full data file.

    The desktop Ask Queries path uses the conversation endpoints. Direct generate_dag endpoints exist for the same generation Capability without a chat session.

    Conversation workflow Desktop chat loop, intents, clarification
    System architecture Capability → Plan → Stage → Artifact
    Telemetry Job state, attempt logs, tokens, credit receipts

    🔐 Authentication

    Every request to /api/v1/* or /api/v2/* must include your API key in the X-API-Key header.

    -H "X-API-Key: <your-api-key>"

    You obtain your API key from the Nolain portal (see User guide and POST /api/auth/keys in Authentication setup).

    Portal account routes under /api/auth/* use a Supabase access token instead:

    -H "Authorization: Bearer <access_token>"

    The exception is GET /api/auth/key-status, which authenticates with X-API-Key (desktop Settings panel).

    Consumption limits

    Consumption is account-based for portal-linked keys. Admission reads profiles_nolain_query.credit_balance and returns 402 Payment Required when the balance is empty.

    Key type Admission Charged per LLM call
    Portal-linked (user_id set) Requires credit_balance > 0 Yes
    Unlinked owner (tier = owner, no user_id) Always admitted No
    Unlinked non-owner 402 —

    Monthly plan grants (see Credits):

    Tier Credits / month
    free 1 000
    premium 50 000

    Queueing a generation job does not consume credits by itself. Each LLM call is charged from token usage plus surplus as soon as it completes. Details: Credits, Billing.

    All LLM traffic routes through OpenRouter. Pass an optional model field (catalog id from GET /api/v1/llm/models); omit it to use the server default (deepseek-v4-flash-0731 unless overridden in llm_models.yaml).

    GET /api/v1/llm/models — Model Catalog

    Lists selectable models and the server default. Uses authentication-only mode.

    curl http://localhost:8000/api/v1/llm/models \
  -H "X-API-Key: sk-your-key-here"

    Response (shape):

    {
  "provider": "openrouter",
  "default_model_id": "deepseek-v4-flash-0731",
  "models": [
    { "id": "deepseek-v4-flash-0731", "label": "DeepSeek V4 Flash (0731)", "openrouter_model": "deepseek/deepseek-v4-flash-0731", "default": true },
    { "id": "gpt-5.6-luna", "label": "GPT-5.6 Luna", "openrouter_model": "openai/gpt-5.6-luna" }
  ]
}

    POST /api/v1/analyze_query — Semantic Analysis 🧠 (Synchronous)

    Analyzes a natural language query to detect ambiguous concepts (polysemy, granularity, vagueness) before DAG generation.

    This direct endpoint charges credits for the LLM call(s) it makes. The same semantic step inside POST /api/v1/conversation/message is also charged when it invokes a model.

    Request Body Parameters

    Field Type Required Description
    query string ✅ Natural language question about your data
    metadata object ✅ Dataset schema info (see Metadata Object)
    model string ❌ Catalog model id (e.g. "deepseek-v4-flash-0731"). Default: server default from llm_models.yaml.
    n_interpretations int ❌ Candidate interpretations per ambiguity. Default: 4.

    POST /api/v2/generate_dag — data_analysis Capability (Asynchronous)

    Admits the registered data_analysis Capability. The server builds a Plan of Stages from request options. The pandas Plan always produces a code_pandas Artifact (pandas_code on the status payload). Optional Stages add a DAG and/or a visualization spec. Each LLM call in the worker is charged as it completes; poll billing.charged_credits on the status payload for the running total.

    Pandas Plan Stages (built from options):

    1. generate_pandas — LLM produces Pandas code from the query + metadata. The worker applies deterministic compatibility patches and static preflight checks (no execution on the server). Truncated (finish_reason=length), empty, syntactically invalid, unsafe, or structurally incomplete code is rejected before delivery and may retry under the adaptive repair policy.
    2. compile_dag — optional (compile_dag=true, default); LLM translates the code into a DAG
    3. format_visualization — optional (include_visualization=true, default); LLM produces a visualization_spec
    4. validate_visualization — optional (when include_visualization=true); validates the chart contract
    5. validate_dag — optional (when compile_dag=true); validates the DAG
    6. finalize_plan — mark success (no separate charge; billing is per LLM call)

    descriptive / visualization / transformation are not Capabilities or Plans. Charts set include_visualization; they do not change plan_id.

    Poll responses include capability_id, plan_id, current_stage, compile_dag, include_visualization, pandas_code, optional graph / visualization_spec, and an optional artifacts[] envelope. Pandas reliability fields are:

    • pandas_retries_left: remaining local-runtime repair jobs
    • pandas_sandbox_retries_left: remaining in-cloud retries
    • pandas_attempts_used / pandas_total_max_attempts: chain usage and ceiling
    • generation_attempts: bounded diagnostics for each LLM call, including finish reason, selected policy profile, token counts, and outcome

    Request Body Parameters

    Field Type Required Description
    query string ✅ Natural language question
    metadata object ✅ Dataset schema info
    model string ❌ Catalog model id
    clarifications array ❌ List of { "term": "...", "chosen_interpretation": "..." }
    compile_dag boolean ❌ Include the optional compile_dag Stage (default true)
    include_visualization boolean ❌ Produce a visualization_spec Artifact (default true)
    capability_id string ❌ Registered Capability id (default data_analysis)
    plan_id string ❌ Catalog Plan id (default data_analysis/pandas)

    POST /api/v1/cancel_task/{task_id} — Cancel a Job

    Cooperative cancellation between Plan Stages. LLM calls already completed keep their credit charges. Restricted to the API key that owns the job.

    Uses authentication-only mode (usable after credits are exhausted).

    curl -X POST http://localhost:8000/api/v1/cancel_task/a1b2c3d4-e5f6-7890-abcd-ef1234567890 \
  -H "X-API-Key: sk-your-key-here"
    HTTP Meaning
    200 Cancellation recorded (status: "cancelled")
    403 Key does not own this job
    404 Job not found
    409 Job can no longer be cancelled

    Conversation endpoints (/api/v1/conversation/*)

    This is the desktop Ask Queries loop. Full branch table: Conversation workflow.

    Sessions live in Redis (conversation:{session_id}) for 24 hours. Session GET/DELETE currently do not verify that the calling key created the session.

    POST /api/v1/conversation/start

    Creates a session. No LLM call; no charge.

    curl -X POST http://localhost:8000/api/v1/conversation/start \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sk-your-key-here" \
  -d '{ "metadata": { "available_columns": ["Country", "Price"] } }'

    { "session_id": "c0a1b2c3-d4e5-6789-abcd-ef1234567890" }

    POST /api/v1/conversation/message

    Main decision + optional job admission.

    Field Type Required Description
    session_id string ✅ From /start
    message string ✅ User text
    metadata object ✅ Dataset schema info
    model string ❌ Catalog model id
    clarifications array ❌ When set, skips classify/semantic and queues generation
    compile_dag boolean ❌ Compile DAG UI toggle (default true)
    include_visualization boolean ❌ Request a chart spec (default true; intent classifier may also set this)
    plan_id string ❌ Optional catalog Plan (default data_analysis/pandas)

    For chart-only queries the intent classifier typically keeps include_visualization=true. Set include_visualization=false when you want pandas/DAG output without a chart spec.

    Without clarifications, LangGraph classifies intent:

    type in response Meaning
    text_response Off-topic, unsafe, underspecified, explanation, out of scope, or semantic failure
    meta_answer Dataset-structure question answered from metadata
    clarification Ambiguous terms; resend with clarifications
    generation Job accepted; poll task_id 
    curl -X POST http://localhost:8000/api/v1/conversation/message \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sk-your-key-here" \
  -d '{
    "session_id": "c0a1b2c3-d4e5-6789-abcd-ef1234567890",
    "message": "Show a bar chart of the top 5 countries by total revenue",
    "metadata": { "available_columns": ["Country", "Quantity", "Price"] },
    "compile_dag": true
  }'

    generation response:

    {
  "type": "generation",
  "task_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "session_id": "c0a1b2c3-d4e5-6789-abcd-ef1234567890",
  "capability_id": "data_analysis",
  "plan_id": "data_analysis/pandas",
  "compile_dag": true,
  "include_visualization": true
}

    Requests that no registered Capability can serve return text_response (out_of_scope) and do not queue generation. Forecasting, statistical inference, optimization, and anomaly detection currently fall in that branch while only data_analysis is enabled. Explanation requests return grounded text from saved result context and do not queue generation.

    POST /api/v1/conversation/result

    Notify the server of local execution so follow-ups have context. No charge on a successful store.

    When exec_error and pandas_code are set, the previous generation job succeeded, that job still has pandas_retries_left > 0, and the chain has not reached pandas_total_max_attempts, the server queues a generate_pandas repair job (same query, failed code + traceback, no classifier). Jobs that already failed in the cloud (syntax/sandbox rejects) are not re-queued as runtime repairs. It carries attempt history forward and resets the sandbox retry budget for the repair job, then returns:

    {
  "status": "repairing",
  "type": "generation",
  "task_id": "...",
  "session_id": "...",
  "capability_id": "data_analysis",
  "plan_id": "data_analysis/pandas",
  "compile_dag": true,
  "include_visualization": true,
  "pandas_retries_left": 1
}

    Poll that task_id and re-execute locally. If no retries remain, the response is { "status": "ok" }.

    curl -X POST http://localhost:8000/api/v1/conversation/result \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sk-your-key-here" \
  -d '{
    "session_id": "c0a1b2c3-d4e5-6789-abcd-ef1234567890",
    "dag": { "graph_id": "...", "nodes": [], "output_node": "node_2" },
    "exec_result": { "preview": [{"Country": "United Kingdom", "revenue": 912345.0}] },
    "pandas_code": "result = df.groupby('Country')['Quantity'].sum()"
  }'

    ❌ Error Responses

    HTTP Code Condition Detail Example
    400 Bad Capability / Plan Unknown or unimplemented plan_id
    401 Unauthorized "X-API-Key header is missing."
    402 No credits "No credits remaining on your account. ..." / unlinked key
    403 Forbidden "Invalid API key." / deactivated key / cancel of another key's job
    404 Not found Session or generation job not found
    409 Conflict Job can no longer be cancelled
    500 Task / agent failure Semantic agent error, or poll dag_status: "failed"
    503 Runtime unavailable Redis, Celery worker, Supabase unreachable, or OPENROUTER_API_KEY missing

    When a portal-linked key has credit_balance <= 0, or a non-owner key has no user_id, most workflow endpoints return 402 before they run — including conversation start/message, metadata answers, and synthesis. Unlinked owner developer keys are exempt. Status poll and cancel remain available (get_api_key_auth_only).
