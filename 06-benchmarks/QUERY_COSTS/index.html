    Query costs and benchmark results

    This page reports observed execution costs instead of modeled case tables. Each run contains 50 hard retail-invoice questions using the desktop conversation loop, a local Pandas engine, and the dataset recorded in each run's parameters.txt.

    Credits are the product's charged credits, not US dollars. The current default is 1,000 credits per dollar plus a 100% surplus; see CREDITS.md for the user-facing formula.

    Results

    GPT-5.6 Luna, Pandas only

    Run: 2026-08-31_08-48-40

    • 50 queries; 49 code executions succeeded (98%).
    • 204 credits were charged: 4.08 average, 4 median, and 8 maximum per query.
    • No Pandas, sandbox, runtime, or compiler retries occurred.
    • Ground-truth comparison was unavailable.

    DeepSeek V4 Flash 0731, Pandas only

    Run: 2026-08-31_09-15-16

    • 50 queries; 35 code executions succeeded (70%).
    • 138 credits were charged: 2.76 average, 2 median, and 8 maximum per query.
    • 23 Pandas retries occurred: 21 sandbox retries and 2 runtime repairs.
    • Ground-truth comparison was unavailable.

    GPT-5.6 Luna, Pandas plus DAG

    Run: 2026-08-31_09-42-01

    • 50 queries; all 50 code executions succeeded (100%).
    • 45 DAG executions succeeded (90%).
    • 1,942 credits were charged: 38.84 average, 42 median, and 50 maximum per query.
    • 1 Pandas retry and 1 sandbox retry occurred; no runtime retries occurred.
    • Pandas and DAG outputs matched for 12 of 38 comparable queries (31.58%).
    • 87 compiler retries occurred, averaging 1.74 per query.
    • Ground-truth comparison was unavailable.

    What these runs show

    • Adding DAG compilation greatly increased observed cost in this sample: 38.84 average credits versus 4.08 for GPT-5.6 Luna without a DAG.
    • The successful code rate was higher with the DAG run, but DAG execution was not perfect and its output matched Pandas in only 31.58% of comparable cases.
    • The DeepSeek run was cheaper, but its 70% code success rate and 23 retries show that cost alone does not describe the user experience.

    These are measurements from one 50-query slice, not a price guarantee or a quality benchmark for every dataset. None of the three runs had ground-truth answers, so accuracy against a known correct answer cannot be concluded.
