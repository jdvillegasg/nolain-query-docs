    Nolain Data Query

    Nolain answers questions about a file that already lives on your computer. You type something like “What is total revenue by country?”, and you get a table — and, if you asked for one, a chart — computed from that file.

    The unusual part is where the work happens. Your file never leaves your machine. A remote service sees only a sketch of the data: column names, types, a few sample rows. It returns a recipe — executable analysis, and optionally a computation graph and a chart contract. Your computer runs that recipe against the real file. The numbers you see are true because they were computed locally, not because a model claimed them.

    This public book is for people who want to use, evaluate, understand, or integrate with Nolain. Choose the route that matches your goal; each route starts with the least context it requires.

    Use Nolain

    1. Follow Using Nolain to create an account, add an API key, and ask a first question.
    2. Use the local first-run guide when you want to run the desktop app from this repository.
    3. Continue with desktop workflows for common tasks.
    4. Check Credits before estimating usage. The troubleshooting guide covers common user-facing failures.

    If you only have twenty minutes, read this page, Using Nolain, and the opening of How Nolain is built.

    Understand Nolain

    Start with How Nolain is built for the privacy split and the principles behind it. Then read The parts of the system for component responsibilities and A conversation from start to finish for one representative end-to-end flow.

    After that foundation, use Clarifications and How a Plan is declared to examine two deeper mechanisms. Query costs provides measured behavior rather than architectural intent.

    Integrate with the Cloud API

    Read Calling the Cloud API for the public HTTP contract, authentication requirements, endpoints, and request examples. The sketch and metadata contract is the focused reference for constructing the compact file description sent to the cloud.

    API integrators do not need maintainer access or the private operational documentation.

    Public and private boundaries

    This book explains public product behavior, architecture, API usage, and measured costs. Repository setup, authentication wiring, billing internals, telemetry, and production deployment belong to the private maintainer book in docs-private/; that book is not published with these pages.

    A few words you will meet again

    You do not need these yet. They are here so later chapters can use them without stopping to define them twice.

    Word Meaning in this book
    Sketch A compact description of a local file: columns, types, summaries, sample values. This is all the cloud is allowed to see.
    Artifact Something the cloud produces for the desktop to use: executable analysis, an optional computation graph, an optional chart contract.
    Capability A product the cloud knows how to generate. Today there is one: descriptive analysis of a single file.
    Plan An engine for a Capability — the sequence of steps that produces artifacts. Today the implemented engine is Pandas.
    Intent What kind of conversational turn this is (answer from the sketch, refuse, ask a clarifying question, or generate analysis). Not a product.
    Credits The unit you pay in. Each call to a language model settles immediately.
