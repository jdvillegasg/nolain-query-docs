    Sketch and metadata

    Nolain sends a compact description of a local dataset to the Cloud API instead of uploading the complete file. This description is the sketch. It gives the model enough schema context to generate analysis, but it is not anonymous: sample rows and sample values can contain real data.

    Where the sketch comes from

    The local engine reads the selected path through:

    GET http://localhost:8001/data_summary?source_path=...

    The response wraps the sketch as {"status":"success","summary":{...}}. For CSV files, the engine uses a reservoir sample of up to 1,000 rows for semantic inference and returns at most 10 of those rows as sample_data. For Parquet files, it inspects the first 1,000 rows and returns the first 10. For Excel, it inspects up to 1,000 rows from the first sheet and returns a sample of at most 10. These limits describe the current sidecar implementation, not a guarantee that every client serializes every field to the cloud.

    Conventional fields

    Cloud request schemas accept metadata as a JSON object rather than enforcing a dedicated metadata model. Current components recognize these fields:

    Field Meaning
    available_columns Ordered column names
    column_semantics Per-column inferred type, semantic type, null ratio, bounded cardinality, and sample values when available
    sample_data Optional bounded sample rows
    total_rows / total_rows_read Optional row-count fields used by metadata answers

    An abbreviated sidecar result can look like:

    {
  "available_columns": ["Quantity", "Price", "Country"],
  "sample_data": [
    {"Quantity": 12, "Price": 6.95, "Country": "United Kingdom"}
  ],
  "column_semantics": {
    "Quantity": {
      "null_ratio": 0.0,
      "cardinality": 500,
      "sample_values": [12],
      "data_type": "int",
      "semantic_type": "numeric"
    }
  }
}

    This output is illustrative and abbreviated; each listed column normally has a column_semantics entry.

    What the desktop sends

    The current Ask Queries serializer requests the full sidecar summary, then sends these fields to conversation endpoints:

    • available_columns
    • column_semantics
    • total_rows
    • total_rows_read

    It currently omits top-level sample_data. However, column_semantics can still contain sample_values. Direct API callers and benchmark clients pass their supplied metadata object through unchanged, so they may include sample_data as well.

    This distinction matters for privacy statements: Nolain does not send the full file or its local path to the Cloud API, but a sketch may contain actual values. Inspect the request you send if those values are sensitive.

    How cloud stages use it

    The conversation classifier receives column names. Metadata-only answers use column names, row counts, and type information when present. Semantic analysis reads column_semantics: routing compares terms with column names, types, descriptions or meanings supplied by a caller, and up to three sample values. Specialist prompts receive a reduced form containing selected statistics and up to three sample_values.

    Once generation is admitted, the worker receives the complete metadata object from the request. The Cloud API does not open or execute the local dataset; generated Pandas code and the optional dag artifact return to the local engine for execution.

    For request fields and endpoints, continue to Calling the Cloud API. For the privacy boundary behind this contract, see The system philosophy.
