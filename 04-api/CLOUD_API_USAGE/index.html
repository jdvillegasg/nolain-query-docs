    Calling the Cloud API

    The previous chapters explained what Nolain is and how a question travels through it. This chapter is the HTTP reference: how a caller authenticates, which doors exist, and what a request looks like.

    There are two doors into the same product.

    • Conversation is what the desktop uses. You open a session on a sketch, send a message, and the server decides whether to reply in text, ask a clarifying question, or queue a generation job. After local execution you report the outcome; the server may repair. This is the full loop in A conversation from start to finish.
    • Direct generation skips the session and the gate. You admit a Capability, poll for artifacts, and execute them yourself. Same dishes, no maître d’, no repair loop.

    Both doors receive a sketch (metadata), never the file. Both return artifacts: Pandas code, and optionally a computation graph and a chart contract. Interactive OpenAPI lives at http://localhost:8000/docs.

    Related chapters: Credits (what a call costs), Billing internals (how charging is implemented), Watching a job (how to read status), Signing in (portal tokens).

    Authentication

    Every request to /api/v1/* or /api/v2/* carries an API key:

    -H "X-API-Key: <your-api-key>"

    Keys come from the Nolain portal, or from POST /api/auth/keys once you are signed in. Portal account routes under /api/auth/* use a Supabase access token instead:

    -H "Authorization: Bearer <access_token>"

    The exception is GET /api/auth/key-status, which authenticates with X-API-Key (the desktop Settings panel).

    Who may spend credits

    Consumption is account-based for portal-linked keys. Admission reads the profile balance and returns 402 Payment Required when it is empty.

    Key type Admitted? Charged per model call?
    Portal-linked (user_id set) Requires remaining credits Yes
    Unlinked owner (tier = owner, no user_id) Always No
    Unlinked non-owner 402 —

    Monthly plan grants: Free 1,000 credits, Premium 50,000. See Credits.

    Queueing a job does not consume credits by itself. Each model call is charged from token usage plus surplus as soon as it completes.

    All model traffic routes through OpenRouter. Pass an optional model field (a catalog id from GET /api/v1/llm/models); omit it to use the server default.

    Health and catalogs

    These endpoints do not generate analysis. They tell you whether the system is up, which models you may pick, and which products the server currently admits.

    GET / — service status

    curl http://localhost:8000/

    {
  "app": "Data Query DAG Generator API",
  "status": "online",
  "documentation": "/docs"
}

    GET /health — runtime health

    Reports Redis, Celery workers, and Supabase. Generation endpoints return 503 when Redis or a worker is unavailable.

    curl http://localhost:8000/health

    {
  "status": "ok",
  "services": {
    "redis": { "ok": true },
    "celery": { "ok": true, "workers": ["celery@host"] },
    "supabase": { "ok": true, "host": "your-project.supabase.co" }
  }
}

    status is "degraded" when any listed service is not ok.

    GET /api/v1/llm/models — model catalog

    Lists selectable models and the server default. Authentication only; does not require remaining credits.

    curl http://localhost:8000/api/v1/llm/models \
  -H "X-API-Key: sk-your-key-here"

    {
  "provider": "openrouter",
  "default_model_id": "deepseek-v4-flash-0731",
  "models": [
    { "id": "deepseek-v4-flash-0731", "label": "DeepSeek V4 Flash (0731)", "openrouter_model": "deepseek/deepseek-v4-flash-0731", "default": true },
    { "id": "gpt-5.6-luna", "label": "GPT-5.6 Luna", "openrouter_model": "openai/gpt-5.6-luna" }
  ]
}

    GET /api/v1/capabilities — Capability / Plan catalog

    Lists registered generation products, their engines, and optional artifacts. Optional artifacts (graph, chart contract) are request options on a Plan, not extra Plan ids.

    curl http://localhost:8000/api/v1/capabilities \
  -H "X-API-Key: sk-your-key-here"

    {
  "capabilities": [
    {
      "id": "data_analysis",
      "enabled": true,
      "plans": [
        {
          "plan_id": "data_analysis/pandas",
          "selectable": true,
          "default": true,
          "implemented": true,
          "engine": "pandas",
          "stages": ["generate_pandas", "compile_dag", "format_visualization", "validate_visualization", "validate_dag", "finalize_plan"],
          "optional_stages": ["compile_dag", "format_visualization", "validate_visualization"],
          "optional_artifacts": ["dag", "visualization_spec"],
          "terminal_artifact_kinds": ["code_pandas", "dag", "visualization_spec"]
        },
        {
          "plan_id": "data_analysis/ibis",
          "selectable": false,
          "implemented": false
        }
      ]
    }
  ]
}

    data_analysis/ibis is catalogued but not selectable. Older Plan ids such as data_analysis/analysis/with_dag map onto data_analysis/pandas plus options.

    Conversation: the desktop loop

    This is the path A conversation from start to finish described. Sessions live in Redis for 24 hours. Session GET/DELETE currently do not verify that the calling key created the session.

    POST /api/v1/conversation/start

    Creates a session. No model call; no charge.

    curl -X POST http://localhost:8000/api/v1/conversation/start \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sk-your-key-here" \
  -d '{ "metadata": { "available_columns": ["Country", "Price"] } }'

    { "session_id": "c0a1b2c3-d4e5-6789-abcd-ef1234567890" }

    POST /api/v1/conversation/message

    The main decision: classify the turn (unless you are answering a clarification) and maybe admit a job.

    Field Type Required Description
    session_id string yes From /start
    message string yes The user’s text
    metadata object yes The sketch (see Metadata)
    model string no Catalog model id
    clarifications array no When set, skips classify/semantic and queues generation
    compile_dag boolean no Compile-DAG toggle (default true)
    include_visualization boolean no Request a chart spec (default true)
    plan_id string no Optional catalog Plan (default data_analysis/pandas)

    The graph and chart toggles are yours. The classifier may suggest a Capability and a Plan; it does not override these options.

    Without clarifications, the server classifies intent and returns one of:

    type in response Meaning
    text_response Off-topic, unsafe, underspecified, explanation, out of scope, or semantic failure
    meta_answer Structure question answered from the sketch
    clarification Ambiguous terms; resend with clarifications
    generation Job accepted; poll task_id 
    curl -X POST http://localhost:8000/api/v1/conversation/message \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sk-your-key-here" \
  -d '{
    "session_id": "c0a1b2c3-d4e5-6789-abcd-ef1234567890",
    "message": "Show a bar chart of the top 5 countries by total revenue",
    "metadata": { "available_columns": ["Country", "Quantity", "Price"] },
    "compile_dag": true
  }'

    {
  "type": "generation",
  "task_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "session_id": "c0a1b2c3-d4e5-6789-abcd-ef1234567890",
  "capability_id": "data_analysis",
  "plan_id": "data_analysis/pandas",
  "compile_dag": true,
  "include_visualization": true
}

    Requests no registered Capability can serve return text_response and do not queue generation. Forecasting, statistical inference, optimization, and anomaly detection currently fall in that branch. Explanation requests return grounded text from saved result context and do not queue generation.

    POST /api/v1/conversation/result

    Notify the server of local execution so follow-ups have context. No charge on a successful store.

    When exec_error and pandas_code are set, the previous generation job succeeded, that job still has pandas_retries_left > 0, and the chain has not reached its attempt ceiling, the server queues a repair job (same question, failed code plus traceback, no classifier). Jobs that already failed in the cloud are not re-queued as runtime repairs. The response:

    {
  "status": "repairing",
  "type": "generation",
  "task_id": "...",
  "session_id": "...",
  "capability_id": "data_analysis",
  "plan_id": "data_analysis/pandas",
  "compile_dag": true,
  "include_visualization": true,
  "pandas_retries_left": 1
}

    Poll that task_id and re-execute locally. If no retries remain, the response is { "status": "ok" }.

    curl -X POST http://localhost:8000/api/v1/conversation/result \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sk-your-key-here" \
  -d '{
    "session_id": "c0a1b2c3-d4e5-6789-abcd-ef1234567890",
    "dag": { "graph_id": "...", "nodes": [], "output_node": "node_2" },
    "exec_result": { "preview": [{"Country": "United Kingdom", "revenue": 912345.0}] },
    "pandas_code": "result = df.groupby('Country')['Quantity'].sum()"
  }'

    POST /api/v1/conversation/synthesize

    Optional post-execution framing. Charges credits if a model is invoked. On failure the endpoint still returns { "status": "success", "narrative": {} }.

    curl -X POST http://localhost:8000/api/v1/conversation/synthesize \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sk-your-key-here" \
  -d '{
    "session_id": "c0a1b2c3-d4e5-6789-abcd-ef1234567890",
    "question": "What are the top 5 countries by total revenue?",
    "result_summary": "United Kingdom leads, followed by France.",
    "outcome": "answered",
    "model": "deepseek-v4-flash-0731"
  }'

    GET / DELETE /api/v1/conversation/{session_id}

    Read or delete the Redis session. Delete returns { "status": "deleted" }. Missing session on GET returns 404.

    Direct generation

    Use this door when you already know you want artifacts and do not need a chat. Prefer POST /api/v2/generate_dag. The v1 endpoint is a legacy planner → compiler chain that does not use the Capability registry.

    Both are asynchronous: they return a task_id. Poll GET /api/v1/get_task_status/{task_id} (next section) for artifacts.

    POST /api/v2/generate_dag — registered Capability

    Admits data_analysis. The server builds a Plan of stages from request options. The Pandas Plan always produces executable code. Optional stages add a graph and/or a chart contract. Each worker model call is charged as it completes; poll billing.charged_credits for the running total.

    Stations, in order, when every optional is on:

    1. Write Pandas code from the question and the sketch. Compatibility patches and a static sandbox check (no execution on the server). Truncated, empty, illegal, or incomplete code is rejected and may retry.
    2. Compile a computation graph from that code (compile_dag=true, default).
    3. Write a chart contract (include_visualization=true, default).
    4. Validate the chart contract.
    5. Validate the graph.
    6. Persist artifacts and finish.

    A chart is a toggle, not a different Plan.

    Field Type Required Description
    query string yes Natural-language question
    metadata object yes The sketch
    model string no Catalog model id
    clarifications array no { "term": "...", "chosen_interpretation": "..." }
    compile_dag boolean no Include the graph (default true)
    include_visualization boolean no Include a chart contract (default true)
    capability_id string no Registered Capability (default data_analysis)
    plan_id string no Catalog Plan (default data_analysis/pandas) 
    curl -X POST http://localhost:8000/api/v2/generate_dag \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sk-your-key-here" \

    Direct generation does not run the conversation repair loop. Reporting POST /conversation/result is a conversation-only move.

    POST /api/v1/generate_dag — legacy planner → compiler

    Starts the older background chain (planner text → graph). Prefer v2 or conversation for the registered Capability.

    Field Type Required Description
    query string yes Natural-language question
    metadata object yes The sketch
    model string no Catalog model id
    n_interpretations int no Interpretations for the planner step
    clarifications array no { "term": "...", "chosen_interpretation": "..." }

    The request body has the same sketch shape as v2. The response is { "status": "queued", "task_id": "..." }.

    POST /api/v1/analyze_query — semantic analysis only

    Polling and cancelling

    GET /api/v1/get_task_status/{task_id}

    Checks progress and retrieves artifacts. Authentication only, so you can still read work that already started after credits are exhausted.

    curl -X GET http://localhost:8000/api/v1/get_task_status/a1b2c3d4-e5f6-7890-abcd-ef1234567890 \
  -H "X-API-Key: sk-your-key-here"

    Useful dag_status values: queued, generating_code, compiling_from_code, formatting_visualization, validating_visualization, validating, finalizing, success, failed, cancelled.

    A successful v2 / conversation poll looks like:

  "execution_status": "SUCCESS",
  "dag_status": "success",
  "graph": {
    "graph_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "nodes": [
      {
        "id": "node_0",
        "op": "filter_extract",
        "params": { "column": "Quantity", "operator": "gt", "value": 100 },
        "inputs": []
      }
    ],
    "output_node": "node_0"
  },
  "errors": [],
  "pandas_code": "result = df.loc[df['Quantity'] > 100].groupby('Country')['revenue'].sum().nlargest(5)",
  "visualization_spec": {
    "version": 1,
    "kind": "bar",
    "title": "Top 5 countries by revenue",
    "x": "Country",
    "y": ["revenue"],
    "sort_direction": "desc"
  },
  "capability_id": "data_analysis",
  "plan_id": "data_analysis/pandas",
  "compile_dag": true,
  "include_visualization": true,
  "billing": {
    "token_credits": 8,
    "surplus_credits": 8,
    "charged_credits": 16,
    "llm_calls": 4,
    "surplus_rate": 1.0
  },
  "artifacts": [
    { "kind": "code_pandas", "schema_version": 1, "storage_key": "pandas_code", "payload": "..." },
    { "kind": "dag", "schema_version": 1, "storage_key": "graph", "payload": {} },
    { "kind": "visualization_spec", "schema_version": 1, "storage_key": "visualization_spec", "payload": {} }
  ]
}

    When compile_dag=false, graph is omitted and pandas_code is the executable artifact. When include_visualization=false, visualization_spec is omitted.

    Execute artifacts on the local engine (port 8001): POST /execute_pandas and, when a graph is present, POST /execute_dag.

    POST /api/v1/cancel_task/{task_id}

    Cooperative cancellation between Plan stages. Model calls already completed keep their charges. Restricted to the API key that owns the job.

    curl -X POST http://localhost:8000/api/v1/cancel_task/a1b2c3d4-e5f6-7890-abcd-ef1234567890 \
  -H "X-API-Key: sk-your-key-here"
    HTTP Meaning
    200 Cancellation recorded
    403 Key does not own this job
    404 Job not found
    409 Job can no longer be cancelled

    Account and billing endpoints

    GET /api/auth/key-status

    Validates an API key (no credit enforcement) and returns whether it can currently spend. Used by desktop Settings.

    curl http://localhost:8000/api/auth/key-status \
  -H "X-API-Key: sk-your-key-here"

    {
  "tier": "free",
  "masked_key": "sk-free-****7890",
  "credit_balance": 42,
  "can_consume": true,
  "is_active": true,
  "label": "Laptop"
}

    credit_balance is null for unlinked keys. can_consume is true for unlinked owner developer keys even then. Portal CRUD for keys (GET /api/auth/me, POST /api/auth/keys, …) uses Bearer tokens — see Signing in.

    Stripe top-ups (/api/billing/*)

    Requires server-side Stripe configuration (see Running the Cloud API yourself).

    POST /api/billing/stripe/checkout creates a Checkout Session. Requires a portal-linked API key. price_id must appear in STRIPE_PRICE_CREDITS_JSON on the server.

    curl -X POST http://localhost:8000/api/billing/stripe/checkout \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sk-your-key-here" \
  -d '{
    "price_id": "price_basic",
    "success_url": "https://nolainquery.com/billing/success",
    "cancel_url": "https://nolainquery.com/billing/cancel"
  }'

    { "checkout_url": "https://checkout.stripe.com/...", "session_id": "cs_..." }

    POST /api/billing/stripe/webhook is the Stripe webhook (no API key). It grants credits on checkout.session.completed when payment succeeds and metadata matches a configured package.

    Data structures

    Metadata object

    This is the sketch: what the cloud is allowed to know about the file.

    {
  "available_columns": ["Invoice", "StockCode", "Description", "Quantity", "InvoiceDate", "Price", "Customer ID", "Country"],
  "sample_data": [
    { "Invoice": "489434", "StockCode": "85048", "Description": "15CM CHRISTMAS GLASS BALL 20 LIGHTS", "Quantity": 12, "InvoiceDate": "2009-12-01 07:45:00", "Price": 6.95, "Customer ID": 13085.0, "Country": "United Kingdom" }
  ],
  "column_semantics": {
    "Invoice": { "null_ratio": 0.0, "cardinality": 28816, "sample_values": ["489434"], "data_type": "string", "semantic_type": "identifier" },
    "Quantity": { "null_ratio": 0.0, "cardinality": 500, "sample_values": [12], "data_type": "int", "semantic_type": "numeric" },
    "Price": { "null_ratio": 0.0, "cardinality": 1606, "sample_values": [6.95], "data_type": "float", "semantic_type": "numeric" },
    "Country": { "null_ratio": 0.0, "cardinality": 37, "sample_values": ["United Kingdom"], "data_type": "string", "semantic_type": "categorical" }
  }
}

    Optional extra fields such as total_rows are used when answering structure questions from the sketch.

    Clarifications array

    Resolves an ambiguous term to a specific interpretation.

    Visualization spec

    A data-free chart contract. The local engine supplies rows at execution time. Supported kind values: line, bar, area, scatter, pie.

    {
  "version": 1,
  "kind": "bar",
  "title": "Top 5 countries by revenue",
  "x": "Country",
  "y": ["revenue"],
  "series": null,
  "sort_by": "revenue",
  "sort_direction": "desc",
  "x_label": "Country",
  "y_label": "Revenue"
}

    Error responses

    HTTP When
    400 Unknown or unimplemented Capability / Plan
    401 Missing X-API-Key
    402 No credits remaining, or unlinked non-owner key
    403 Invalid or deactivated key, or cancel of another key’s job
    404 Session or generation job not found
    409 Job can no longer be cancelled
    500 Task or agent failure; or poll dag_status: "failed"
    503 Redis, Celery worker, or Supabase unreachable, or OpenRouter key missing

    When a portal-linked key has no remaining credits, or a non-owner key has no portal account, most workflow endpoints return 402 before they run — including conversation start/message, metadata answers, and synthesis. Unlinked owner developer keys are exempt. Status poll and cancel remain available.
